# fabweb — Версионирование

Формат: **MAJOR.MINOR.PATCH** (`X.Y.Z`)

Единый источник версии: файл [`VERSION`](../VERSION) в корне репозитория.  
Свод правил проекта: [`RULES.md`](RULES.md).

---

## Правила инкремента

| Тип изменения | Пример | Инкремент | Было → Стало |
|---------------|--------|-----------|--------------|
| **Мелкая правка** | fix UI, typo, мелкий баг, refactor без API | `X.Y.Z+1` | 0.2.0 → **0.2.1** |
| **Средняя правка** | новый экран, расширение API, новые поля, workflow | `X.Y+1.0` | 0.2.1 → **0.3.0** |
| **Глобальное / новый модуль** | breaking API, sync, mobile, смена платформы | `X+1.0.0` | 0.3.0 → **1.0.0** |

До `1.0.0` новый доменный модуль (Auth, Projects, WorkOrders) обычно идёт как **minor**, чтобы `1.0.0` остался маркером готового MVP.

---

## Что синхронизировать при bump

После изменения `VERSION` выполнить:

```bash
pnpm version:sync
```

Скрипт обновит:
- `package.json` (root, apps/*, packages/*)
- `packages/shared/src/version.ts`
- health endpoint автоматически читает из shared

Вручную проверить:
- sidebar в web (`AppLayout`)
- `ARCHITECTURE.md` / `AI_CONTEXT.md` при смене major

## Semver до 1.0.0

Пока версия `< 1.0.0`, API может меняться без major bump.  
Первый **1.0.0** — стабильный MVP для площадки (Pi + offline sync).
